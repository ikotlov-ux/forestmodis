# ForestMODIS

Воспроизводимый конвейер на Python для оценки **динамики лесного покрова, его фрагментации, функционального состояния и относительной структурно-функциональной уязвимости** только по готовым продуктам MODIS Collection 6.1 (без Landsat и без обучения классификаторов). Период по умолчанию — 2003–2024. Расчёт идёт по годам, а результаты представлены с шагом 5 лет (опорные годы 2004, 2009, 2014, 2019, 2024 и пятилетние периоды).

Скрипт сам находит и скачивает гранулы, применяет маски качества, приводит все слои к единой равновеликой сетке, выполняет все этапы анализа и собирает **пакет материалов для анализа** (`outputs/analysis_package/`). По нему исследователь или ИИ-ассистент может подготовить отчёт или научную статью. Научная интерпретация результатов остаётся за исследователем.

## Используемые продукты

| Продукт | Назначение | Разрешение |
|---|---|---|
| MCD12Q1 (LC_Type1, IGBP) | классы покрова 1, 3, 4, 5, 8, 9; кандидатные переходы | 500 м, год |
| MOD44B (Percent_Tree_Cover) | древесное покрытие, пороговые маски, снижения и восстановление | 250 м, год |
| MOD13Q1 / MYD13Q1 | EVI/NDVI (Terra и Aqua раздельно) | 250 м, 16 сут |
| MCD15A2H | LAI, FPAR | 500 м, 8 сут |
| MOD17A2HGF | GPP (накопленная за сезон) | 500 м, 8 сут |
| MOD16A2GF | ET, PET, отношение ET/PET | 500 м, 8 сут |
| MOD11A2 / MYD11A2 | LST день/ночь (по умолчанию объясняющий фактор) | 1 км, 8 сут |
| MCD64A1 | гари, повторяемость пожаров, послепожарный отклик | 500 м, месяц |

Используются классы IGBP: 1 — вечнозелёные хвойные; 3 — листопадные хвойные (в Европейской России это преимущественно лиственничные леса и культуры); 4 — листопадные широколиственные/мелколиственные; 5 — смешанные; 8 — редколесья с сомкнутостью 30–60 % (IGBP Woody Savannas); 9 — разреженные древесные сообщества 10–30 % (IGBP Savannas).

## Этапы

`validate → inventory → plan → download → prepare → landcover → treecover → fragmentation → functional → fire → associations → vulnerability → sensitivity → export`

- **prepare** — QA-маски до перепроецирования, сезонные статистики (май–сентябрь, июнь–август), пропорциональное распределение 8-суточных сумм GPP/ET по сезону, годовые гари.
- **landcover** — площади классов (исходные и модальные по 3 годам), кандидатные устойчивые переходы (≥ N лет до и после, цензурирование на краях ряда, согласованность с MOD44B), матрицы переходов.
- **treecover** — тренды PTC (Сенн + Манн–Кендалл), устойчивые снижения, время восстановления.
- **fragmentation** — собственная реализация метрик класса (CA, PLAND, NP, PD, AREA_MN/MD, LPI, ED, TCA, CPLAND, CORE_SHARE, COHESION, MESH, ENN_MN) в окнах 25 км (чувствительность 10 и 50 км) для масок PTC ≥ порога, сомкнутых, разреженных и всех древесных классов. NoData не считается фоном.
- **functional** — аномалии относительно базового периода, неблагоприятные годы, устойчивые снижения и невосстановление.
- **fire** — частота гарей и послепожарный отклик EVI.
- **associations** — панель по окнам: связи фрагментации, функциональных показателей, LST и гарей с лагами 0–2 года (описательные, не причинные).
- **vulnerability** — компоненты S_cover, S_config, F, H, E, Q с ранжированием, сохраняющим нули, внутри страт; интегралы P_SF = √(S·F), P_fire = (H·E·P_SF)^(1/3). Статус — **provisional**, это относительный приоритет, а не абсолютная оценка риска.
- **sensitivity** — пороги PTC, размер окна, глубина края, устойчивость переходов, базовый период, агрегация, роль LST.
- **export** — пакет `analysis_package`: `START_HERE.md`, методы (RU/EN), словарь данных, каталог результатов, ключевые результаты, годовые и пятилетние сводки, тренды, чувствительность, качество и ограничения, подписи рисунков, инструкции для ИИ, реестр утверждений (claims registry), `manifest.json` с контрольными суммами.

Каждый этап сохраняет хеш конфигурации, поэтому при `--resume` уже выполненные этапы пропускаются. Если параметры этапа изменились, этап и все зависящие от него пересчитываются.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
```

Для HDF4 нужен `pyhdf` (или GDAL с драйвером HDF4). На Windows проще всего поставить через conda: `conda install -c conda-forge pyhdf rasterio geopandas`.

## Доступ к данным NASA (Earthdata Login)

Поиск гранул (`inventory`, `plan`) работает без авторизации. Для скачивания нужна бесплатная учётная запись [NASA Earthdata](https://urs.earthdata.nasa.gov/users/new). Задайте её одним из способов:

- файл `~/.netrc` (на Windows `%USERPROFILE%\_netrc`):
  ```
  machine urs.earthdata.nasa.gov login ВАШ_ЛОГИН password ВАШ_ПАРОЛЬ
  ```
- или переменные окружения `EARTHDATA_USERNAME` и `EARTHDATA_PASSWORD`.

Пароли не пишутся в журналы и в конфигурацию.

### Источник данных: LP DAAC или LAADS DAAC

По умолчанию (`data.source: auto`) скрипт перед поиском гранул проверяет сеть. Из некоторых сетей серверы CMR и LP DAAC обрывают соединение после первых 12–16 КБ: короткие ответы проходят, длинные зависают до тайм-аута. В таком случае скрипт сам переключается на [LAADS DAAC](https://ladsweb.modaps.eosdis.nasa.gov). Там лежат те же файлы MODIS C6.1 с теми же именами, а каталог дополнительно содержит точные размеры и контрольные суммы MD5.

Для скачивания с LAADS нужен токен Earthdata (Bearer):

1. Войдите на [urs.earthdata.nasa.gov](https://urs.earthdata.nasa.gov) → Generate Token.
2. Сохраните токен одной строкой в файл `.earthdata_token` в папке проекта или в домашней папке, либо задайте переменную среды `EARTHDATA_TOKEN`.

Если токена нет, а логин и пароль заданы через `_netrc`, скрипт попробует получить токен сам. В пошаговом режиме он попросит вставить токен и сохранит его в `.earthdata_token`. Токен действует 60 дней.

Если DNS-сервер VPN не находит домены `*.nasa.gov` (ошибка `getaddrinfo failed`; так ведёт себя, например, DNS AmneziaVPN), скрипт сам получает адреса через DNS-over-HTTPS (Cloudflare, Google). Соединение при этом остаётся HTTPS с проверкой сертификата. Можно и просто сменить DNS в настройках VPN на 1.1.1.1 или 8.8.8.8.

Чтобы задать источник явно, укажите в `config.yaml`: `data.source: lpdaac` или `data.source: laads`. Если недоступны оба источника, включите VPN или прокси: переменные `HTTPS_PROXY`/`HTTP_PROXY` учитываются. Другой вариант — скачать HDF на другом компьютере и запустить скрипт с `data.mode: offline`.

## Быстрый старт

```bash
python forestmodis.py init --project D:\work\central_russia
# положите полигон территории в D:\work\central_russia\inputs\aoi.gpkg
python forestmodis.py validate  --config D:\work\central_russia\config.yaml
python forestmodis.py inventory --config D:\work\central_russia\config.yaml
python forestmodis.py plan      --config D:\work\central_russia\config.yaml
python forestmodis.py download  --config D:\work\central_russia\config.yaml
python forestmodis.py run       --config D:\work\central_russia\config.yaml
python forestmodis.py sensitivity --config D:\work\central_russia\config.yaml
python forestmodis.py export    --config D:\work\central_russia\config.yaml
```

Если `--config` не указан, открывается окно Проводника для выбора файла. Команда `python forestmodis.py interactive` ведёт по шагам с окнами выбора AOI и папки проекта.

### Запуск из JupyterLab или IDE

Если запустить скрипт без аргументов (`%run forestmodis.py`, кнопка Run в IDE, двойной щелчок), включается пошаговый режим. Сначала открывается окно выбора `config.yaml`. Если нажать «Отмена», скрипт предложит выбрать папку нового проекта и полигон территории, затем спросит годы. После этого появится меню действий: поиск гранул и план, загрузка, расчёт, чувствительность, экспорт.

Отдельные команды в Jupyter:

```python
%run forestmodis.py validate --config D:/work/central_russia/config.yaml
# или
import forestmodis as fm
fm.main(["inventory", "--config", "D:/work/central_russia/config.yaml"])
```

Частичный перезапуск: `run --from-stage functional --to-stage export`; принудительный пересчёт: `--no-resume`; офлайн-режим по уже скачанному архиву: `--offline`.

## Проверка

- `pytest tests/` — юнит-тесты декодеров QA, календарей композитов, геопривязки тайлов, Манна–Кендалла/Сенна, BH-поправки, детекции переходов (устойчивость, мерцание, цензурирование, согласованность с PTC), детекции снижений PTC, метрик фрагментации (MESH, ED, CORE, ENN, обработка NoData), ранжирования и геометрического среднего.
- `tests/make_synthetic_modis.py` — генератор **синтетических** гранул HDF4 с реальными именами, названиями SDS, типами и геопривязкой тайла h20v03. В них заложены известные сигналы (вырубка, смена пород, засуха, пожар, облачные пропуски), поэтому можно проверить весь конвейер офлайн без Earthdata. Синтетические результаты не имеют научного смысла.
- `examples/config_european_russia_inventory.yaml` и `examples/aoi_european_russia.gpkg` — проверка инвентаризации реальных гранул NASA CMR для европейской части России. Контур приближённый: Natural Earth 1:50m, обрезан по 60° в. д.

## Результаты проверки (13.11.2026)

- Юнит-тесты: 22 из 22 пройдены.
- Синтетический офлайн-прогон (тайл h20v03, AOI 37–40° в. д., 54,5–56,5° с. ш., 2003–2008, 810 гранул): все 9 этапов, чувствительность (16 сценариев) и экспорт выполнены. Обработка одного года занимает около 167 с. Заложенные сигналы восстановлены:
  - засуха 2005 г.: EVI −0,08, GPP −25 %, ET/PET −36 %, LST днём +3 K;
  - вырубка 2006 г.: 6880 ячеек, медианная глубина снижения PTC 36 п.п. при заложенных 35;
  - пожар 2004 г.: 2281 ячейка при заложенных около 2240;
  - смена пород 1→4 в 2006 г.: 3392 подтверждённых пикселя, одиночное мерцание меток отброшено.
- Реальная инвентаризация NASA CMR для европейской части России (2003–2024): 9 тайлов (h19v01–h21v04), 26 202 гранулы, все продукт-годы полные. MCD64A1 не выпускается для арктических тайлов h19v01 и h20v01, поэтому эти тайлы исключены из ожидаемого числа гранул. Оценка загрузки — около 961 ГБ, из них MOD13Q1 и MYD13Q1 — 726 ГБ. Сетка 500 м — 5327×6930 ячеек, площадь AOI около 3,89 млн км².

## Объём данных

Для европейской части России (9 тайлов MODIS, 2003–2024) нужно 26 202 гранулы, около 961 ГБ. Если исключить MYD13Q1 (`data.products`), объём сократится примерно на 350 ГБ. Точную оценку объёма, времени и дискового пространства даёт `plan` по результатам `inventory`. Для первого реального прогона разумно начать с одной-двух областей или с укороченного периода.

## Ограничения

- Регистр битов QA и масштабных коэффициентов собран по User Guide продуктов C6.1. При первом чтении каждого продукта скрипт сверяет масштаб с атрибутами HDF и пишет предупреждение при расхождении. Таблицы QA всё же стоит проверить по актуальным User Guide.
- Переходы MCD12Q1 — **кандидатные**: без независимой валидации они не являются подтверждённой сменой пород.
- MCD12Q1 после 2021 г. имеет повышенную неопределённость, такие результаты маркируются отдельно.
- Формулы интегральной уязвимости предварительные (`provisional`). Их нужно согласовать с коллективом до публикации.
- Связи в блоке associations описательные и не доказывают причинности.
